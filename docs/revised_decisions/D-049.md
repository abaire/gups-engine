## Event dispatch and hooks (§4.4, §5.6)

### D-049 Cascade depth counts every script entry — `rejected`
Needs revision (Alternative 1):
1. Retain the policy that self-only hooks, timer callbacks, and affect callbacks all count toward the depth-8 limit (`CASCADE_MAX_DEPTH = 8`) alongside dispatched events.
2. Enforce the cascade guard check uniformly across all three script entry points: `World.dispatch`, `World.invokeOn`, and `World.invokeRef` (e.g. via a shared `withCascadeGuard` helper).
3. If `cascadeDepth >= CASCADE_MAX_DEPTH`, immediately record a `"cascade"` diagnostic row and drop the invocation, closing the loophole where `invokeOn` and `invokeRef` incremented `cascadeDepth` without checking the limit and allowed unchecked recursion.
*Code:* `World.dispatch`, `World.invokeOn`, `World.invokeRef`, `Hooks.kt`.
