## Kotlin seams and types (§3, §4.11)

### D-056 Player names are unique among in-world players — `rejected`
Needs revision:
1. Prevent player name collisions at character creation time: character registration in `auth` (`AccountLogin`, `Names`, `AccountStore`)
   must reject any player name that collides (case-insensitively) with:
   - Any existing player in the database / account store.
   - Any registered NPC / mob prototype name or keyword across loaded world packages (`world.protos.mobs.values`).
   - Reserved commands, exits, and system names.
2. This eliminates player-NPC spoofing (e.g. players naming themselves after mobs like "guard", "goblin", or "barkeep" to deceive players or spoof command resolution).
3. By enforcing global uniqueness against all players and registered NPCs at creation time, the ad-hoc in-world player duplicate check in `World.spawnPlayer` is obviated (in-world checks need only assert that the same authenticated character session is not logged in concurrently).
*Code:* `World.spawnPlayer`, `AccountLogin`, `Names.kt`, `AccountStore`.
