## Rules, simulation and content (§4.2–§4.7, §5.7–§5.9) — M5

### D-108 The rules module and its fallback — `rejected`
Needs revision (Alternative A accepted):
1. **Load-time export validation:** When loading `//rules:combat.star` (or any custom rules package specified in tests), `ScriptLoader` must validate all public top-level functions (symbols not prefixed with `_`). Any public function that does not match a known `RulesExport` name must emit a diagnostic warning/error indicating an unrecognized export, catching typos like `def tohit(ctx):` instead of silently ignoring them.
2. **Spec clarification:** Update SPEC §4.6 to clarify that `//rules:combat.star` exports are optional overrides: any unexported functions fall back to the built-in Kotlin ruleset (`DefaultRules`).
3. **Runtime fallback retained:** The runtime fallback mechanism (falling back to Kotlin for an individual call on script error, step-limit hit, or invalid return value, along with throttled instructor alerts at most once per minute per function) is retained as designed.
