## Combat (§5.4)

### D-042 Dispel filter syntax — `rejected`
Needs revision:
1. Replace the string-based filter parameter with structured Starlark arguments:
   `dispel(name = None, flag = None, all = False, count = None)`.
   - `flag`: string or list of strings matching against `affect.flags` (e.g. `flag = "curse"`, `flag = "poison"`).
   - `name`: string matching exact `affect.name` or wildcard prefix ending in `*` (e.g. `name = "shield"`, `name = "curse_*"`).
   - `all`: boolean; if `True`, matches all non-intrinsic affects.
   - `count`: optional integer; if set, dispels at most `count` matching affects (default: `None`, removing all matching).
   - Validate at package load time that at least one of `name`, `flag`, or `all = True` is provided.
2. Intrinsic Protection: affects with flag `"intrinsic"` are immune to dispel (even when `all = True`).
3. Dispelling an affect removes it from `target.affects`, invokes its removal trigger with reason `REMOVED` (per D-041), and outputs its `expireMessage`.
4. **General Architectural Directive (Structure over Micro-DSLs):** Establish a core engine rule that the engine
   and Starlark schemas must consistently rely on structured arguments and native Starlark types (keyword arguments,
   lists, dicts, schemas) rather than inventing ad-hoc string-based micro-DSLs. Expressiveness and schema validation
   are primary reasons for choosing Starlark.
*Code:* `Effect.Dispel`, `World.applyEffect`, `Declarations.dispel`.
