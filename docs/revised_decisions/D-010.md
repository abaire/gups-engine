## Scheduler and initiative tiers (§5.1, §5.4.1)

### D-010 Shutdown — `rejected`
Needs revision: the shutdown timeout (currently hardcoded at 30 s) should be configurable
(e.g. via server configuration). `Shutdown(delayPulses, reason)` broadcasts the reason and
stops the loop once the delay has passed. The server then takes the final checkpoint (§5.11)
on the world thread and waits up to the configured timeout for the writer to commit it,
including on a JVM shutdown (Ctrl-C).
*Code:* `World.handle(WorldControlEvent)`, `WorldLoop.run`, `GupsServer.run`, `Commands.kt`.
