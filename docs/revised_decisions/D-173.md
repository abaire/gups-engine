## Documentation, API stability and plugins (§1.3, §4.15–§4.17, §7.2) — M7

### D-173 Changelog grammar details (SPEC §4.17) — `rejected`
Needs revision:
1. **Remove machine-parsed changelog DSL:** Delete the rigid, line-by-line grammar state machine in `Changelog.kt` (`Changelog.parse`, `Parser`, metadata blocks `- kind:`, `- symbol:`, `- replacement:`). `CHANGELOG.md` should be standard, human-readable Markdown (or scraped/generated from conventional commit messages) rather than a compiler-enforced DSL.
2. **Remove `changes.json`:** Drop `changes.json` generation and serialization. Modern LLMs and human readers consume Markdown directly; an intermediate JSON representation is redundant.
3. **Spec Change Proposal (SPEC §1.3):** Propose removing the explicit requirement for `MIGRATING.md` from `docs/SPEC.md` §1.3. How migration guides are provided or produced by students in course exercises is an operational curriculum detail, not a core engine architectural component.
4. **Remove `gups migrate-info`:** Delete the `gups migrate-info` CLI command (`MigrateInfoCmd`) and AST matcher (`MigrateInfo.kt`). Migration analysis will rely on students providing the human-readable changelog directly to an LLM.
5. **Downstream impact on D-174 (API diff check):** Reorient `ApiDiff` to compare `api.json` baselines directly to detect breaking changes and version bumps without cross-validating against changelog metadata.
*Code:* `script/src/main/kotlin/gups/script/Changelog.kt`, `cli/src/main/kotlin/gups/cli/DocsRenderer.kt`, `script/src/test/kotlin/gups/script/ChangelogTest.kt`, `docs/SPEC.md` §1.3.
